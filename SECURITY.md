# Sécurité / Security Policy

[Français](#français) · [English](#english)

## Français

### Versions concernées

Nous examinons en priorité les signalements concernant la dernière version
stable. Vous pouvez également signaler une faille touchant une version plus
ancienne ; indiquez sa version exacte. Aucun délai de correction ou de prise
en charge des anciennes versions n'est garanti.

### Signaler une vulnérabilité

Utilisez le [signalement privé de GitHub](https://github.com/jpierre-amar/zrepo-rs/security/advisories/new).
N'ouvrez pas d'issue publique et ne publiez pas de preuve de concept avant
qu'une correction puisse être préparée. Indiquez la version et le système
concernés, les étapes de reproduction, l'impact possible et une preuve de concept
minimale. Retirez tout jeton, clé, donnée personnelle ou adresse de serveur de
vos pièces jointes.

Le périmètre comprend le lanceur, l'accès GitHub et SSH, le clonage, la gestion
des identifiants, les installeurs et la mise à jour de zrepo-rs. Les problèmes
de fonctionnement sans conséquence de sécurité peuvent être signalés dans les
[issues publiques](https://github.com/jpierre-amar/zrepo-rs/issues).

Nous accuserons réception dans le signalement privé, examinerons l'impact et
coordonnerons la correction et sa publication avec la personne qui a signalé
la faille. Aucun délai de réponse fixe n'est promis.

## English

### Supported versions

We prioritize reports affecting the latest stable release. You may also report
an issue affecting an older release; include the exact version. We do not
guarantee a fix timeline or maintenance for older releases.

### Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/jpierre-amar/zrepo-rs/security/advisories/new).
Do not open a public issue or publish a proof of concept before a fix can be
prepared. Include the affected version and operating system, reproduction
steps, potential impact, and a minimal proof of concept. Remove tokens, keys,
personal data, and server addresses from attachments.

The scope includes the launcher, GitHub and SSH access, cloning, credential
handling, installers, and updates for zrepo-rs. Functional bugs without a
security impact can be reported in [public issues](https://github.com/jpierre-amar/zrepo-rs/issues).

We will acknowledge the private report, assess its impact, and coordinate the
fix and disclosure with the reporter. We do not promise a fixed response time.
